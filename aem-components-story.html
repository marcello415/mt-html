How a product page comes together in AEM 6

A storyboard of how I built and kept up product pages on mt.com/rainin, using the SmartStand page as the example. Each step shows what happens in AEM, with an example from the real page, and what my part was.

Where
Mettler-Toledo Rainin, as Web Producer
Scale
Website and store content in 23 markets
My role
Pages, components, assets, catalog, translations, SEO
Tools
AEM 6 classic UI, DAM, SAP Commerce Cloud, Welocalize

The copy, product numbers and image paths come from the archived SmartStand page (April 2019). The illustrations are drawn for this page.

  1. Step 1 · The page

    A product page is a set of tabs and sections

    Every Rainin product page followed the same pattern: a header with the product name, then tabs for the overview, products and specs, documentation, services and a video. Every product page was organized the same way.

    My partBuilding new product pages from that pattern and keeping existing ones current.

  2. Step 2 · Components

    Each tab is a stack of components

    Inside each tab is a paragraph system: a container you drop components into, in any order. Text, text and image, mood images, carousels and videos all came from a shared component library, so layouts stayed consistent from page to page.

    In AEM 6 classic UI I had a lot of control here: which components to use, in what order, and how each one was set up.

    My partChoosing and arranging components for each page from the library, instead of custom layouts.

  3. Step 3 · The dialog

    Every component has a dialog

    Double-click a component in edit mode and its dialog opens: the fields for that component. Change the copy or swap the image, press OK, and the page updates in place.

    My partWriting and updating the copy in each component, and picking images from the DAM.

  4. Step 4 · Assets

    Images come from the DAM, in the right size

    Photos are uploaded to the DAM once. When a component uses one, it loads a web rendition AEM made from the original, so pages get a right-sized image without anyone resizing it by hand.

    My partManaging the Rainin assets in the DAM and placing them on pages.

  5. Step 5 · Products and the store

    The website and the store have to agree

    The same products were sold in the online store, which ran on SAP Commerce Cloud. When a product changed, the store listing and the product page both had to change, with the same names and material numbers.

    My partKeeping catalogs current for the North American storefronts and checking store listings against the website after each update.

  6. Step 6 · 23 markets

    English first, then every market

    Pages were written in English, sent to Welocalize for translation, and published market by market. Each translated page was compared to the English source before it went live, so no market ended up with missing sections or old copy.

    My partRunning localization for 23 markets: sending content, publishing translations and checking them against the source.

  7. Step 7 · Publish and follow up

    Activate, then watch how it does

    Once a page was right in author, it was activated to the live site. The work didn’t stop there: SEO tools flagged on-page issues to fix, and dashboards showed whether visitors were finding and using the page.

    My partFixing on-page SEO issues found in Ahrefs, AccuRanker and Searchmetrics, and building conversion and engagement dashboards in Adobe Analytics and Google Analytics.
    1. 01ActivatePage goes live from author.
    2. 02CheckStore listings match the page.
    3. 03SEOFix on-page issues, then re-check rankings.
    4. 04MeasureConversion and engagement dashboards.

Where it carries over

Any AEM site built from a component library works this way: pages assembled from shared parts, images from the DAM, and content kept in step with the store and every market. That’s the work I’d bring.
